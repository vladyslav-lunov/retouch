# retouch-lab

Автоматика ретуші шкіри та видалення об'єктів. Вихід — **шари корекції**,
а не готовий піксель: видно, що система зробила, і кожен дотик можна
послабити або скасувати в Photoshop.

## Встановлення

```bash
pip install --only-binary=:all: dist/retouch_lab-0.1.0-py3-none-any.whl
```

`--only-binary` тут не про акуратність. Без нього pip на macOS 12 не
знаходить сумісного колеса opencv, мовчки падає на збірку зі сирців і
годинами крутить cmake. З ним — або ставиться за хвилину, або одразу
каже, що колеса немає.

Розробка — з репозиторію, без встановлення:

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install --only-binary=:all: -r requirements.txt
python3 tests/test_blemish.py        # має бути зелено
```

## Спробувати за одну хвилину

Реальних кадрів у репозиторії немає і не буде, тому є генератор макета:

```bash
python3 scripts/make_fixture.py -o fixtures
retouch fixtures/PORTRAIT.tif -o out --preview
open out/PORTRAIT_preview.png
```

`--preview` — головний спосіб подивитися, що вийшло, не збираючи документ
у Photoshop. Зверху загальний план (до, після, різниця ×4, що знайдено,
маска, покриття), знизу — **кропи 1:1** навколо найконтрастніших плям.

> Про якість ретуші судити можна ЛИШЕ за кропами 1:1. Зменшений до екрана
> портрет 24 Мп не показує роботи по текстурі взагалі — там нема чого
> дивитися за визначенням.

Макет — це макет: він перевіряє логіку, а не якість. Пороги на ньому не
калібрують, див. `spec.md` §6.2.

## Інтерфейс

```bash
retouch-ui                      # відкриє браузер на 127.0.0.1:8765
retouch-ui portrait.tif         # одразу з відкритим кадром
```

Шість вкладок: **Перегляд** (загальний план), **1:1** (клац по кадру —
вирізки до/після в рідних пікселях), **Маска** (пензлем правити, що
система вважає шкірою), **Плями** (зняти галочку — не лікувати),
**Видалення** (замалювати людину чи предмет — дірка заповнюється фоном,
не прозорістю), **Калібрування** (той самий кадр кількома порогами, §6.2).

Ручні правки маски переживають зміну параметрів: вони лягають ПОВЕРХ
автоматичної маски, а не замість неї. Попередження про неправдоподібну
маску тут показується панеллю, а не зупиняє роботу, — рішення за людиною.

## Робота з реальним кадром

RAW читається напряму — CR3, NEF, ARW, DNG і решта:

```bash
retouch IMG_0059.CR3 -o out --preview
```

Демозаїк чужий, свій ми не пишемо (spec.md §4). Два шляхи:

| | ставиться | якість |
|---|---|---|
| **rawpy** (libraw) | `pip install rawpy` | керована, відтворювана |
| **ImageIO** | нічого, є в macOS | рендер Apple |

Перевага в rawpy автоматично, якщо він є. Різниця не косметична: Apple
підмішує шумозаглушення й різкість у високу частоту, тобто рівно туди,
де працює конвеєр — на тому самому порозі виходить 4613 «дефектів»
проти 1478. Чим прочитано, видно в рядку `[read] ... raw=rawpy`;
примусово — `--raw-decoder`.

**Основним входом лишається 16-бітний TIFF з Camera Raw**: ACR — це
проявник, під який калібрувалися пороги.

```bash
retouch portrait.tif --dry-run              # скільки дефектів, нічого не пише
retouch portrait.tif -o out --preview       # прогін + аркуш
retouch portrait.tif -o out --debug         # + усі проміжні шари
```

```
out/portrait_00_base.tif     оригінал, вихідна розрядність
out/portrait_01_skin.png     шар лікування шкіри (16-біт RGBA)
out/portrait_02_remove.png   шар видалення об'єктів
out/portrait_mask_skin.png   що система вважала шкірою
out/portrait_99_flat.tif     зведений результат
out/portrait_preview.png     оглядовий аркуш
out/portrait_debug/          з --debug: усі проміжні етапи
```

У Photoshop: відкрити `_00_base.tif`, покласти зверху `_01_skin.png`,
крутити opacity або домальовувати маску шару. Або `scripts/assemble.jsx`.

## Корисні прапорці

| | |
|---|---|
| `--dry-run` | порахувати дефекти, нічого не писати |
| `--preview` | оглядовий аркуш з кропами 1:1 |
| `--limit 30` | прибрати лише 30 найпомітніших |
| `--strength 0.7` | послабити лікування |
| `--threshold 0.018` | менш агресивна детекція |
| `--search-radius 60` | як далеко шукати донора |
| `--debug` | скинути всі проміжні шари |
| `--remove-mask m.png` | біла маска = що видалити |
| `--config c.yaml` | параметри файлом (прапорці мають пріоритет) |
| `--force-mask` | прогнати попри неправдоподібну маску шкіри |

## Перевірка себе

```bash
python3 tests/test_blemish.py       # інваріанти ядра
python3 tests/test_inpaint.py       # інваріанти видалення
python3 scripts/selftest.py         # табель на макеті: що знайшло, куди полізло
python3 scripts/selftest.py --sweep # таблиця по порогах
python3 scripts/bench.py --mp 24    # бюджет часу й пам'яті, spec.md §9
```

`selftest.py` відповідає на питання, на яке тести не відповідають:
не «чи не зламалося», а «наскільки добре». На макеті відома істина —
де кожен дефект і де кожна зона виключення, — тож повнота і хибні
спрацювання рахуються, а не вгадуються.

## Моделі — не опція, а умова

Без моделей маска шкіри евристична (YCrCb), інпейнт — Telea. На макеті
це просто гірше: евристика захоплює 82% брів і 100% верхньої губи.
На реальному вуличному портреті — непридатно.

Заміряно на кадрі 26 Мп (бежева аркада, бежеве пальто, шкіра): маска
віддала **91% кадру**, радіус вийшов 20.8 px замість 4.7, детектор
знайшов 4558 «дефектів» по каменю й волоссю, а лікування порізало
волосини й затерло ланцюжок. Це не налаштовується порогами: YCrCb —
тест на колір, а не на обличчя, і на фоні кольору шкіри він безпорадний.

Тому конвеєр **зупиняється**, якщо маска накрила понад 60% кадру, і
пояснює, що робити. Обійти свідомо — `--force-mask`.

Кроп голови не рятує: перевірено на чотирьох масштабах, маска лишається
90-95% навіть на щільному кропі обличчя, бо русяве волосся за кольором
теж «шкіра». Лікування тоді йде по волоссю, бровах і контурі губ.

Висновок: до підключення face-parsing інструмент придатний лише там, де
маска ВИБІРКОВА — темне волосся і фон не кольору шкіри. Тобто студія на
рівному тлі. Конвеєр сам зупиняється, коли це не так.

Допоміжне, поки моделі немає:

```bash
python3 scripts/crop_face.py IMG.tif        # вирізати голову (каскад Хаара)
```

```bash
python3 scripts/fetch_models.py     # підказки, звідки брати
retouch p.tif --face-model models/face.onnx --lama-model models/lama.onnx
```

Далі — `spec.md`.
