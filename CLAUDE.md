# CLAUDE.md — конвенції проєкту

Читай `spec.md` перед будь-якою зміною. Він описує НАВІЩО, цей файл — ЯК.

## Запуск

```bash
python3 tests/run_all.py               # усі набори, мають бути зелені
python3 tests/test_blemish.py          # окремий набір, якщо треба швидко
python3 -m retouch.cli IMG.tif -o out --debug
python3 -m retouch.cli IMG.tif --dry-run    # лише порахувати дефекти
python3 scripts/bench.py --mp 24            # бюджет часу й пам'яті, spec.md §9
python3 scripts/make_fixture.py -o fixtures # макет портрета для ручних прогонів
python3 scripts/check_face_model.py M.onnx IMG.tif   # перевірити ваги ДО довіри
python3 -m retouch.cli fixtures/PORTRAIT.tif -o out --preview
python3 -m retouch.webui                    # локальний UI, порт 8765
python3 -m retouch.cli --schema             # схема пресету для агента
python3 scripts/brief.py IMG.CR3 -o brief   # досьє на кадр ДЛЯ агента
python3 scripts/variants.py IMG.tif presets/*.yaml -o var   # порівняти пресети
python3 -m retouch.cli IMG.tif --preset p.yaml --preset frame.yaml
python3 -m retouch.cli SHOOT/ -o out --batch --preset shoot.yaml   # ніч
python3 -m retouch.cli IMG.tif -o out --dodge-burn --db-strength 0.6
```

`--preview` кладе поруч із шарами один PNG: загальний план плюс кропи
1:1 навколо найконтрастніших плям. Судити про якість ретуші можна ЛИШЕ
за кропами 1:1 — зменшений портрет не показує роботи по текстурі взагалі.

Залежності ставити ТІЛЬКИ так:

```bash
pip install --only-binary=:all: -r requirements.txt
```

Для RAW додатково (не обов'язково, але краще):

```bash
pip install --only-binary=:all: rawpy
```

Для моделей (face-parsing, LaMa) — **тільки на Python 3.9-3.12**:

```bash
pip install --only-binary=:all: "dist/retouch_lab-0.1.0-py3-none-any.whl[raw]" "onnxruntime<1.20"
```

Пакета `retouch-lab` на PyPI немає — ставиться зі шляху до колеса.
`pip install retouch-lab[raw]` дасть "No matching distribution found".

Колеса onnxruntime для Intel macOS з 1.20 збираються під macosx_13_0, а
тут Monterey 12. Остання придатна версія — 1.19.2 (macOS>=11.0), і для
cp313 сумісних колес НЕМАЄ ЖОДНОГО. Тобто на Python 3.13 модельна гілка
конвеєра просто не запуститься. Робоче середовище — Python 3.9: на ньому
разом стають numpy, opencv, rawpy і onnxruntime без конфліктів
(перевірено). Це та сама пастка, що зі стелею opencv, тільки дорожча:
без ONNX немає ні face-parsing, ні LaMa, тобто немає v0.2 і v0.3.

Без rawpy RAW читається через macOS ImageIO. Це працює, але Apple додає
своє шумозаглушення й різкість у високу частоту, і на тому самому порозі
знаходиться втричі більше «дефектів» (spec.md §4). Порівнювати прогони
між різними декодерами не можна — це різні вхідні дані.

Без `--only-binary` pip на Monterey мовчки не знаходить колесо opencv,
падає на збірку зі сирців і годинами крутить cmake на двох ядрах.
Стеля версії в `requirements.txt` стоїть з тієї ж причини — не знімати,
не перевіривши, чи є колесо під `macosx_12_0_x86_64`.

## Інваріанти — не ламати

Ці сім речей перевіряються тестами. Якщо зміна їх ламає — зміна
неправильна, навіть якщо результат виглядає краще:

1. лікування не змінює низьку частоту;
2. поза `coverage` вихід ідентичний входу до біта;
3. `base·(1−a) + layer·a == result` (інакше Photoshop покаже не те);
4. детектор ловить ≥80% відомих дефектів на синтетиці;
5. без донора пляма ПРОПУСКАЄТЬСЯ, а не лікується абияк;
6. лікування не тримає буферів розміру кадру — інакше конвеєр не
   запуститься на 8 ГБ (spec.md §2);
7. лікування не виходить за маску шкіри — ні на піксель.

## Стиль

- Усе всередині — `float32` BGR у `[0..1]`. Конвертації тільки на межах I/O.
- Параметри — через дата-класи (`DetectParams`, `MaskParams`, `Config`),
  не через голі аргументи. Дефолт має бути в дата-класі, не в сигнатурі.
- Модулі не знають одне про одного, крім `blemish -> freqsep`.
  Оркестрація живе тільки в `pipeline.py`.
- Коментарі українською, ідентифікатори англійською.
- Коментар пояснює РІШЕННЯ, а не переказує код. «чому boxFilter, а не
  цикл» — так; «фільтруємо зображення» — ні.

## Реальність, з якою треба рахуватися

Евристична маска шкіри на вуличному портреті віддає 90+% кадру — камінь,
тканина і шкіра лежать в одному діапазоні YCrCb. Конвеєр після цього
шкодить кадру, а не покращує його (заміряно, spec.md §5). Тому:

- перевіряти зміни в детекції та лікуванні ТІЛЬКИ на кадрах, де маска
  правдоподібна: макет `make_face`, студійний кадр або ручний кроп голови;
- не робити висновків про пороги з прогону, де маска > 60% — конвеєр там
  зупиняється сам і не дарма;
- поки не підключено face-parsing, будь-яке калібрування порогів
  безпідставне: поріг міряється поверх маски;
- face-parsing вимагає КРОПА ГОЛОВИ — на повний кадр його не подавати
  (spec.md §15.1). Кроп робить YuNet усередині build_skin_mask;
- нове поле в дата-класі — це нове поле в схемі пресету.Описувати
  ОБОВ'ЯЗКОВО рядком під полем: агент має розуміти параметр, інакше не
  обґрунтує його в `why` (spec.md §1.2). Тест це перевіряє;
- «шкіра» — це рішення фотографа, а не властивість пікселя. Перш ніж
  ускладнювати детектор, спитати, чи не знімається проблема галочкою
  в наборі класів (§15).

## Чого не робити без окремої розмови

- не додавати згладжування шкіри розмиттям — це проти суті проєкту;
- не міняти порядок етапів: пластика ПЕРЕД шкірою (spec.md §14.2), бо
  інакше ретуш робиться по пікселях, які деформація потім пересемплить;
- не міняти знак у полі зміщення: там лежить, ЗВІДКИ брати піксель;
- не переходити на тайлову обробку, поки не доведено, що впирається в RAM;
- не додавати залежностей понад `requirements.txt`;
- не міняти дефолтні параметри, не перезамірявши таблицю з §6.2 spec.md;
- не робити конвеєр, що віддає ТІЛЬКИ зведений файл без шарів.

## Позначки в коді

`ПЕРЕВІР` — припущення про зовнішній контракт (порядок класів моделі,
формат входів ONNX). Не вважати перевіреним, поки не прогнано на
реальному файлі ваг.
